Create & import flashcards

How Creator works

Start with a deck name and class. Each card has a front and a back: the front is what you want to recall, and the back is the answer, formula, explanation, example, or diagram.

Simple card Front: What is force?
Back: A push or pull that can change motion.
Formula card Front: Newton's second law
Back: \(F = ma\), where m is mass and a is acceleration.

Formatting tools

Use bold, italic, underline, highlights, colors, lists, quotes, code blocks, horizontal rules, and LaTeX math. Keep formatting useful: highlight the idea, not the whole answer.

formatted answer 
Front: Compare arteries and veins
Back:
<ul>
  <li><b>Arteries:</b> carry blood away from the heart</li>
  <li><b>Veins:</b> carry blood toward the heart</li>
</ul>

Special card types

  • Basic: one front and one back. Best for definitions, formulas, and direct questions.
  • Reverse: makes a second card from answer to question. Best for vocabulary and terms.
  • Cloze: hide part of a sentence with {{c1::answer}}. Best for facts in context.
  • Media: attach images, audio, or video to either side.
  • Image occlusion: place masks over image labels or parts. Each mask becomes a study card.
  • Advanced HTML/CSS: make a designed 340 x 470 card for tables, flowcharts, timelines, process summaries, and formula cards.

Make cards that are easy to review

  • One memory point per card: split lists, exceptions, dates, steps, and formulas into separate prompts when they feel heavy.
  • Ask a real question: write prompts like "Which hormone lowers blood glucose?" instead of vague prompts like "Insulin".
  • Keep answers compact: use one line, a tiny table, or short bullets. Put only the recall-critical explanation on the back.
  • Use tags: tags such as chapter-2, diagram, formula, or weak make cards easier to find later.
  • Prefer recognition plus recall: diagrams, cloze deletions, and reverse cards are powerful only when they test something specific.

Rich text and math

Normal cards allow safe study formatting: bold, italic, underline, lists, blockquotes, code, preformatted code, horizontal lines, highlights, colored spans, and LaTeX math. Use \(...\) for inline math and \[...\] for display math.

math-and-list.html 
<b>Ohm's law:</b> \(V = IR\)
<ul>
  <li>V = potential difference</li>
  <li>I = current</li>
  <li>R = resistance</li>
</ul>

Cloze and reverse examples

Cloze cards hide answers inside a sentence. If one card has {{c1::...}} and {{c2::...}}, Erudite creates separate recall cards for those blanks. Reverse cards are better for terms that should be remembered both ways.

Cloze The SI unit of force is {{c1::newton}} and its symbol is {{c2::N}}.
Reverse Front: Mitochondria
Back: Site of aerobic respiration
Reverse also asks: Site of aerobic respiration -> Mitochondria.

Media, backgrounds, and occlusion

Attach images/audio/video when the media is part of the memory. Background images are visual context for a side of a normal card. Image occlusion is different: add a diagram, place masks over labels or parts, and each mask becomes its own study card with an answer and optional hint. For AI-made occlusion decks, pixel boxes are safest: use the final cropped image size and one box per real label or part.

Use media Pronunciation audio, a map, an apparatus photo, a graph, a labelled diagram, or an original source image.
Use occlusion Hide "stigma", "style", and "ovary" on a flower diagram so each hidden label is tested separately.

Advanced HTML/CSS cards

Use this only when a normal card is too flat: comparison tables, timelines, flowcharts, formula summaries, process diagrams, and dense visual revision cards. The design lives in a 340px x 470px card canvas. Put structure in HTML and styling in CSS. Avoid JavaScript, external links, form controls, iframes, fixed/sticky layers, and decorative designs that slow review.

advanced-html-shape 
frontHtml: <div class="card-design"><h2>Mitosis</h2><p>Order the stages.</p></div>
frontCss: *{box-sizing:border-box}.card-design{width:340px;min-height:470px;border-radius:20px;overflow:auto;padding:18px;background:#fff;color:#111}

Import file

Use the Creator screen's Import file button for new card content. Use TXT for quick cards, JSON for structured cards, and ZIP for media-heavy decks. Full backups still use Import Backup.

Uses your separator settings. Default format:

Use spreadsheet columns. Headers are optional. Recognized header aliases (case-insensitive, spaces/underscores ignored):

  • Front/Term: term, front, question, prompt, text, cloze
  • Back/Definition: definition, back, answer, meaning
  • Tags: tags, tag
  • Reverse: reverse
  • Card Type: type, cardtype, notetype
cards.csv

ZIP package

Use .zip for image-heavy decks. It must contain one deck.json plus a media/ folder.

structure.txt 
evolution.zip
  deck.json
  media/
    fig_miller_experiment.webp
    fig_homologous_organs.webp

Inside deck.json, reference files like this:

deck.json (ZIP version) 
{
  "version": 1,
  "name": "Evolution",
  "cards": [
    {
      "type": "basic",
      "term": "<img src=\"media/fig_miller_experiment.webp\" alt=\"Miller experiment\">",
      "definition": "Explain the Miller-Urey experiment."
    }
  ]
}

Keep media local to the package. Use paths like media/file.webp; avoid external URLs and giant Base64 strings.

Auto-Attached Images: If you use an HTML image tag (e.g., <img src="media/file.webp">) in a normal card, Erudite automatically converts it into a native attached image during import.

Copy this for an AI

This section is not a user questionnaire. It is a raw technical guide for any AI model that needs to create Erudite TXT, JSON, or ZIP flashcards.

erudite-ai-format-guide.txt 
You are creating importable study decks for Erudite.

Your job:
- Convert source material into flashcards, not notes.
- Each card should test one clear memory point.
- Keep answers compact and reviewable.
- Preserve exact source facts, names, dates, formulas, examples, diagrams, labels, and terminology.
- Do not invent unsupported facts.
- Do not include SRS/review metadata: no id, noteId, srs, reviewHistory, due, reps, lapses, streaks, analytics, created, or lastModified.
- Keep the final deck under 999 cards.

Choose one output style:
1. TXT: fastest, plain front/back cards only.
2. JSON: structured cards, cloze, reverse, tags, image occlusion with Base64 images, advanced HTML/CSS.
3. ZIP: best for media-heavy decks; deck.json plus media files.

Core card quality rules:
- Good: "Which hormone lowers blood glucose?;Insulin."
- Bad: "Insulin;Important hormone." The prompt is too vague.
- Prefer "What changes?" "Which part?" "Why?" "Formula?" "Exception?" "Compare A vs B?".
- Split overloaded answers into multiple cards.
- Use cloze for facts inside sentences.
- Use reverse cards only when back-to-front recall is useful.
- Use media/occlusion only when it improves memory.
- Use advanced HTML only for tables, timelines, flowcharts, process maps, formula summaries, and compact visual revision.

Normal rich text allowed in term/definition:
- Safe simple HTML: b, strong, i, em, u, br, div, p, ul, ol, li, span, mark, code, pre, blockquote, hr.
- Colored text can use span style="color:#2563eb".
- Highlight classes can use mark class="highlight-yellow", "highlight-green", "highlight-blue", or "highlight-pink".
- Math can use \(F = ma\) for inline math or \[x^2 + y^2\] for display math.
- Do not use scripts, iframes, forms, external links, or interactive controls.

TXT guide:
- Return plain text only.
- Use ; between front and back.
- Use @ between cards.
- Do not use @ inside card text.
- Avoid semicolons inside card text.
- TXT cannot carry tags, card types, media, cloze metadata, image occlusion, or advanced HTML.
- Format:
Front 1;Back 1@Front 2;Back 2@Front 3;Back 3
- Example:
Photosynthesis;Process by which green plants make glucose using sunlight, carbon dioxide, and water.@Mitochondria;Site of aerobic respiration in the cell.@Newton's second law;\(F = ma\).

JSON guide:
- Return valid JSON only.
- Do not wrap in Markdown.
- Do not add comments, prose, headings, or trailing commas.
- Root shape:
{
  "version": 1,
  "name": "Deck name",
  "className": "Optional class name",
  "cards": []
}

Accepted aliases:
- Front fields: term, front, question, prompt, text, cloze.
- Back fields: definition, back, answer, meaning.
- Type fields: type, cardType, noteType.
- Tags: tags array or comma-separated string.
- Reverse: true, yes, 1, on, or reverse.

Card type values:
- basic
- reverse
- cloze
- image-occlusion
- advanced-html

Image occlusion card:
{
  "type": "image-occlusion",
  "term": "Flower diagram",
  "image": { "dataUrl": "data:image/png;base64,BASE64_IMAGE_DATA", "width": 1200, "height": 800 },
  "occlusion": {
    "guessMode": "hide-all",
    "units": "px",
    "imageWidth": 1200,
    "imageHeight": 800,
    "masks": [
      { "shape": "rect", "bboxPx": [480, 160, 216, 72], "answer": "Stigma", "hint": "Top receptive part" },
      { "shape": "ellipse", "bboxPx": [552, 288, 168, 80], "answer": "Ovary" }
    ]
  },
  "tags": ["diagram", "flower"]
}

Image occlusion rules:
- Direct JSON must use an image data URL.
- ZIP deck.json may use "image": "media/file.webp".
- Best AI-safe mask format: set occlusion.units to "px", include occlusion.imageWidth and occlusion.imageHeight, and use bboxPx: [left, top, width, height].
- Pixel boxes must be measured on the final cropped image that Erudite will display, not the PDF page and not a screenshot with a different scale.
- guessMode "hide-all" (default) covers every label and asks one; "hide-one" leaves the other labels visible as context.
- Normalized x/y/w/h values from 0 to 1 also work when you are certain they are relative to the final image.
- If using normalized boxes, x and y are top-left position; w and h are width and height.
- shape is rect or ellipse.
- Every mask needs answer. hint is optional.
- Each mask becomes a separate study card.
- If one diagram/image has several labels to test, create ONE image-occlusion card using that image and put ALL label masks in the same occlusion.masks array. Do not duplicate the same image into many one-mask cards. Erudite automatically turns each mask into its own study card.
- Use image occlusion for labels, anatomy, maps, apparatus, graphs, and diagrams where hiding a part tests recall.
- Do not add extra masks for arrows, decorative text, repeated labels, uncertain labels, captions, or parts you cannot name confidently.
- For crowded diagrams, use about 3-12 high-value masks per image. Split into multiple cropped images only when one full image is too crowded or unreadable.

Advanced HTML rules:
- Use HTML and CSS only.
- HTML and CSS are stored separately: frontHtml, frontCss, backHtml, backCss.
- HTML should use one root wrapper such as <div class="card-design">.
- Canvas target: 340px wide, 470px tall, 20px radius.
- CSS must include *{box-sizing:border-box}.
- Root wrapper should use width:340px; min-height:470px; border-radius:20px; overflow:auto or overflow:hidden.
- Allowed useful HTML includes div, section, article, headings, p, span, strong, em, mark, code, pre, blockquote, lists, tables, img, sup, sub.
- Do not use JavaScript, scripts, event attributes, style attributes in HTML, iframes, forms, inputs, buttons, select, textarea, canvas, audio, video, external URLs, @import, fixed/sticky positioning, or z-index tricks.
- CSS may reference package media only with url("media/file.webp") in ZIP mode.
- Advanced HTML is for useful visual structure, not decoration.

ZIP guide:
- Create a normal downloadable .zip file.
- The ZIP must contain deck.json at the root.
- The ZIP should contain media/ when media files are referenced.
- deck.json uses the same JSON schema as above.
- In ZIP mode, use media paths instead of Base64:

      "tags": ["evolution", "experiment"]
    },
    {
      "type": "image-occlusion",
      "term": "Flower diagram",
      "image": "media/flower_diagram.webp",
      "occlusion": {
        "units": "px",
        "imageWidth": 1200,
        "imageHeight": 800,
        "masks": [
          { "shape": "rect", "bboxPx": [480, 160, 216, 72], "answer": "Stigma" }
        ]
      }
    },

      "term": "Timeline of events",
      "definition": "Visual timeline",
      "advancedHtml": {
        "frontHtml": "<div class=\"card-design\"><h2>Timeline</h2><img src=\"media/timeline.webp\" alt=\"Timeline\"></div>",

ZIP media rules:
- Every media/... reference in deck.json must exist inside media/.
- Do not use external URLs.
- Do not reference files outside media/.
- Do not put Base64 media inside deck.json for ZIP output.
- For image occlusion in ZIP mode, mask boxes should be measured on the exact media image referenced by deck.json.
- Safe media extensions: .webp, .png, .jpg, .jpeg, .gif, .mp3, .wav, .ogg, .mp4, .webm.
- Prefer lowercase filenames with letters, numbers, hyphens, and underscores.
- Example ZIP structure:
deck.json
media/
  flower_diagram.webp
  miller_experiment.webp
  timeline.webp

- Return Erudite Package Source instead.
